# 附录 术语表

[返回母文档](../README.md)

- CRM：客户关系管理。这里包含联系人、沟通、商机和工作安排
- 租户 / organization：使用系统的一家组织。组织边界也是主要的数据隔离边界
- 成员关系 / membership：登录用户在某个组织中的身份与角色
- 联系人 / contact：业务上的客户或联系对象，不等于登录账户
- 商机 / lead：一次销售机会。界面可能按行业显示为订单等名称
- 漏斗 / pipeline：组织销售阶段的结构；看板是它的一种展示方式
- 阶段 / stage：商机当前所在的位置，可能关联赢单或失单含义
- 会话 / conversation：围绕联系人和渠道形成的沟通线程
- 消息 / message：会话内的一条输入、输出或其他记录；创建成功不等于外部送达
- 跟进 / follow-up：按规则或安排继续处理业务的任务，不等于所有 CRM 待办
- Agent：在约束内调用模型和工具完成任务的软件执行者
- Run：一次持久运行，有自己的标识、状态、事件和结果
- 工具 / tool：Agent 可请求的受控能力，仍必须遵守产品权限
- specialist：执行有界子任务的专职 Agent，子运行不因此获得任意写权限
- Pi：本项目采用的 Agent 循环运行内核
- provider：模型或相关能力的服务提供方
- BYOK：使用组织自己配置的模型凭据。配置存在不代表当前连接可用
- 模型绑定 / binding：本次执行选择的 provider、模型及关联配置
- proposal：需要通过规则或人工决策的动作提案；数据结构存在不证明入口已接通
- 幂等 / idempotency：相同业务操作重试时，避免重复产生不该重复的效果
- 租约 / lease：某个 Worker 在有效期内处理任务的临时资格
- SSE：服务器向客户端持续发送事件的 HTTP 通道
- RLS：数据库行级安全策略，限制某个身份可访问哪些行
- RBAC：按角色控制操作权限；菜单隐藏不能替代服务器检查
- service role：高权限服务器身份。绕过 RLS 时必须自行保留组织范围
- OCC：乐观并发控制。提交时比较旧版本，避免悄悄覆盖别人的更新
- Wiki：本书说的产品 Wiki 是组织知识资料，不是这份 CodeWiki 网站
- 客户记忆：已确认的客户事实及其来源、版本和撤回状态
- 组织记忆：组织范围内的版本化上下文，与个人客户事实不同
- Mem0：此处用于已确认事实投影与相关性排序，不能覆盖 SQL 权威事实
- RAG：先检索材料，再让模型在检索证据上回答
- chunk：切分后的资料片段，用于索引与检索
- embedding：把文本编码成便于相似度检索的向量
- evidence：带来源定位与适用范围的依据，不是任意模型生成文本
- claim：需要被依据支持的事实声明或结构化断言
- Eval：评测一项运行或结果的方法与报告
- Judge：对有界运行材料进行语义审查的模型，不是最终业务验收负责人
- needs_review：仍需复核，不能改写为通过
- OTLP：OpenTelemetry 的数据传输协议；Langfuse 适配用它接收观测数据
- trace：串起一次任务相关活动的观测标识
- span：trace 中一段有起止时间的活动，例如一次模型或工具调用
- fixture：可重现的测试资料或响应。合成 fixture 不能冒充真实渠道或客户数据
- Worker：长时间运行并领取后台任务的进程；它可以调用 Agent，但自身不等于 Agent
- 模型网关 / Model Gateway：统一处理模型绑定、组织凭据、调用约束和用量记录的服务器入口
- checkpoint：恢复或压缩上下文使用的检查点。客户服务摘要检查点与 Pi 运行快照有不同结构和适用范围
- outbox：与业务变化关联的待发送记录。是否与业务变化同事务写入，要看具体实现
- inbox 去重记录：记录已接收的外部事件身份，帮助识别平台重复投递；不同于产品的会话收件箱 Inbox
- fingerprint：对指定材料计算的指纹，用于判断内容是否变化；它不自动证明材料正确
- 同步请求：调用方等待这次 HTTP 处理的直接结果
- 异步任务：请求先交付可持久追踪的任务，再由消费者处理；入队成功不等于执行成功
- 事务：一组数据库操作共同提交或共同回滚的范围；函数先后调用不等于在同一事务内
- fencing：让旧执行者在失去资格后无法提交受保护操作的隔离方式。执行前检查与原子提交检查强度不同
- 缓存失效：把资料副本标为需要刷新，再从权威来源读取；不是删除业务事实
- Mission：跨 Run 保存业务目标、预算和状态的任务记录；一个 Mission 可以关联多个 Run，不是聊天历史的容器
- Harness：包围模型运行的控制代码，负责权限、工具、状态、预算和记录；不是另一位模型
- observation：记录实际模型或工具执行结果的观察材料；模型在答案里声称成功不能替代实际 observation
- revision：某份内容或记录的版本标识，用于检查是否已发生变化；版本号存在不等于内容正确
- pointer：指向当前使用版本的引用。修改 pointer 不会把旧版本的历史内容改写成新版本
