# 医械智枢：医疗器械销售与服务 Agent 平台适配方案

> 状态：规划稿，2026-10-15；项目展示名于 2026-10-16 确定为“医械智枢”。范围是基于 AiNativeCrm 规划“医疗器械厂商销售与服务”场景，并制作可核验的求职演示；**不是半岛医疗的官方项目、合作声明或实际系统部署**。本文件不授权抓取客户数据、接入官网表单、使用品牌素材或发布 Agent。

## 1. 结论与产品定位

官网呈现的主体是医疗器械研发、生产和销售企业，不是单一诊所。网站有面向医疗机构的设备咨询表单（姓名、手机、医院类型、城市、意向设备）、产品中心、装机/培训/维护/维修/巡检/延保服务，以及设备、治疗头、合作机构、推荐医师四类验真指引。因此，适配目标是：

**机构咨询 → 需求识别 → 产品资料检索 → 销售接管与报价审批 → 成交/交付 → 已售设备服务 → 结案与反馈。**

另设消费者咨询与验真指引支线，但不将“诊疗建议”或“官方验真结果”作为 Agent 的自动输出。

调研来源：[公司与业务](https://www.peninsula-med.com/about.html?loc=2)、[产品中心](https://www.peninsula-med.com/solution.html)、[联系表单](https://www.peninsula-med.com/contact_us.html)、[客户服务](https://www.peninsula-med.com/customer_service.html)、[四重验真](https://www.peninsula-med.com/authenticity.html)。这些是公开网页描述，不等于内部业务规则或可用 API。

## 2. 两种交付边界

### A. 求职演示版（优先）

- 用虚构机构、联系人、设备型号/编号、工单和报价；可展示完整交互链路。
- Agent 的“检索、建商机、提交审批、创建服务请求”等动作可在本地测试环境运行；若发布到 GitHub Pages，则必须明确标为预录/模拟，不宣称连接真实模型、数据库或官网。
- 不使用半岛医疗 Logo、官方身份、真实客户信息、疗效宣传或“官方验真成功”画面，除非取得明确授权。

### B. 真实企业接入（独立决策）

- 需要企业授权、正式业务规则、产品资料和注册/宣传内容审校、渠道及数据接口、隐私与合规评审。
- 官网表单、企微、设备序列号或验真系统都不能仅靠公开网页推断接口；没有接口时使用人工录入或官方页面跳转，不伪造连通。
- 医疗健康信息可能是敏感个人信息；演示与首版 B2B 销售均不采集病历、治疗照片、诊断或其他不必要的健康信息。参考[《个人信息保护法》](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)。

## 3. 现有系统复用与缺口

可复用的底座：联系人与商机 `app/api/v1/contacts/`、`app/api/v1/leads/`；Agent 与知识库 `app/api/v1/ai/agents/`、`app/api/v1/ai/knowledge/`；follow-up、人工案例 `app/api/v1/ai/cases/`、日程 `app/api/v1/agenda/`；RLS、审计、事件队列与人工接管链路。复用前必须在实际运行环境逐项验证，而不是把“有路由”视为功能已闭环。

关键缺口：

1. **机构客户模型。** 当前 tenant `organizations` 是安装方/租户，不可当作客户医院；需要“机构客户—科室/地区—联系人—商机”的独立关系。
2. **设备与已售资产。** 现有 `catalog_products` 是按 SKU 和固定售价设计的商店目录；设备询价不能填虚构 `0` 价格来勉强复用。需决定产品资料模型，以及成交后“设备型号—序列号—安装机构—维保状态”的资产模型。
3. **报价权责。** Agent 能收集需求与准备草稿，但折扣、价格、交期和合同由授权人员确认；需显式审批及版本留痕。
4. **售后工单。** 现有 `ai/cases` 是人工接管案例，是否扩展为服务请求或新建服务实体，要在数据设计阶段确认；不能把普通聊天案例直接称作维修工单。
5. **官方验真。** 公开网站提供验真操作指引，不证明有可用接口；没有授权数据源时只能导流到官方渠道。
6. **国内渠道。** 项目目前以 WhatsApp 为主；官网表单、企微等需要独立接入与渠道约束，不应把 WhatsApp 逻辑复制进新业务模块。

## 4. 阶段任务与目标

### 阶段 0：业务确认与证据边界（启动门槛）

**目标：**确定是作品演示还是企业真实项目，锁定一条主要业务链，收集可信的规则与素材。

任务：

- 明确受众和范围：机构采购/渠道销售优先；消费者咨询仅作为单独支线。确认是否存在任何真实合作或品牌使用授权。
- 按角色访谈或模拟访谈销售、区域负责人、售后工程师、产品/合规负责人；列出咨询类型、分派规则、报价权限、服务时限、关单条件。
- 整理资料清单：产品说明、型号/注册信息、适用范围与禁忌、安装培训、维修/延保、官方验真渠道；给每份资料标注来源、版本、负责人和有效期。
- 写出“不知道/未授权”清单：价格、折扣、交期、服务 SLA、官网接口、验真接口、企微接入、个人信息处理授权。未获确认前一律不写入 Agent 的事实库。

交付物：业务边界说明、角色与权限矩阵、资料台账、演示数据规范、待确认问题清单。

验收：每项拟自动化动作都有来源和责任人；每项对外承诺有人工决策者；演示素材不含真实客户数据且不暗示官方合作。

### 阶段 1：业务对象与流程模型（P0）

**目标：**让“机构需求”成为可追踪对象，而不是散落在聊天、联系人和商机里。

任务：

- 建立机构客户与联系人关系：机构类型、城市/区域、科室、联系人职务、联系方式；区分客户机构与 tenant `organizations`。
- 确定需求/商机的身份、来源、负责人、当前阶段、下一步、到期时间和结局；一条对话允许关联多种需求，同一需求允许跨渠道持续。
- 设计两条独立流程：设备销售（新咨询→需求确认→资料匹配→演示/方案→报价审批→成交/未成交）和售后服务（受理→核验设备→派工→处理→客户确认→关闭/重开）。销售“成交”不能自动等于装机完成。
- 做 DIRC 评审：哪些信息引用联系人/机构/设备，哪些需要独立实体，避免把机构名、型号名或负责人邮箱当关联键。
- 在数据模型评审中决定产品目录是扩展现有目录还是新建设备型号表；对于无公开价产品，不造默认价格。

交付物：领域模型/ADR、字段与状态字典、事件和权限矩阵、架构图、迁移方案草案。

验收：每个未结需求都有负责人和下一步；商机、已售资产和售后请求不混为一体；跨租户不可见；状态转换和结案原因可解释。

### 阶段 2：线索入口与分派（P0）

**目标：**机构咨询进入系统后，不因来源、重复提交或无人接单而丢失。

任务：

- 先做独立的演示表单/受控导入，字段参考官网但不直接调用其生产接口；记录来源、同意记录和去重依据。
- 以机构类型、地区、意向设备、咨询目的区分销售线索、售后问题、培训咨询、消费者验真咨询；未知类型进入人工待分派队列。
- 复用现有 CRM 联系人、商机、时间线和区域/负责人分派能力；缺少配置时显示“待分派”告警，而非静默失败。
- 建立首响和未处理提醒；重复提交走幂等与合并审查，不生成多个相同商机。

交付物：线索接入流程、分派配置、异常/待分派视图、浏览器演示脚本。

验收：测试线索从提交到商机可追溯；无负责人、重复提交和非法输入均有可见结果；任何开放需求都有下一动作或明确关闭原因。

### 阶段 3：可审校的设备知识库（P0）

**目标：**Agent 只基于已批准、当前有效的资料回答，能明确表达不知道。

任务：

- 按产品型号、适用对象、注册/认证资料、配置、安装条件、常见问题、售后政策建立知识分类；把事实、营销表述和内部销售规则分开。
- 所有来源经过人工审核后发布；对过期、撤回、冲突版本实施失效与重索引。回答保留来源、版本及时间。
- 对“治疗效果、适宜人群、禁忌、风险、医生资质、价格、交期”设置更高置信和人工审核边界；不从一般科普推断具体个人治疗方案。
- 建立对抗测试：旧产品版本、互相矛盾的资料、缺失价格、越权跨机构资料、诱导 Agent 保证疗效。

交付物：知识来源台账、发布/撤回流程、问答测试集、未覆盖问题清单。

验收：指定测试问题可定位到有效来源；过期资料不会被引用；无依据时转人工而不是补造事实；跨 tenant 检索隔离通过测试。

### 阶段 4：销售 Agent 与人工报价（P0；演示版第一里程碑）

**目标：**展示 Agent 真正操作 CRM，同时把价格、承诺和医疗判断留给有权人员。

任务：

- 配置“机构咨询 Agent”：逐项收集机构、地区、使用场景、意向设备、采购/演示时间；检索知识、写 CRM 摘要、建议下一步。
- 如同一渠道需要多角色，再增加售后/消费者路由；先证明单 Agent 闭环，避免为了展示多 Agent 而制造空转。
- Agent 可形成产品匹配理由、演示预约建议和报价草稿；正式价格、折扣、供货与装机交期必须经过有权销售/负责人批准。
- 人工接管时交付已知事实、资料引用、未解决问题、已做动作和下一步；人工处理后结构化回写，Agent 才能继续。
- 对发送、更新商机、预约、提交报价分别配置明确工具与权限；关键外发需可取消/审核窗口，所有结果写活动日志并在界面可见。

交付物：Agent 草稿配置、权限与工具清单、人工审批页/复用方案、完整销售场景录制。

验收：至少覆盖正常询价、资料不足、价格越权、要求疗效保证、客户转人工、人工改价六类场景；未经批准不出现正式报价或交期；演示能从线索走到“人工已确认下一步”，不是只输出聊天文本。

### 阶段 5：装机与售后服务闭环（P1；演示版第二里程碑）

**目标：**把成交后的设备与服务请求关联起来，避免销售结束后客户问题失联。

任务：

- 建立已售设备登记：型号、序列号、安装机构、安装/培训记录、保修/延保状态；数据由授权人员录入或可信系统同步。
- 设计维修/维护/巡检/培训/升级等服务请求，含故障描述、紧急程度、负责人、下一动作、到期时间、处理记录和客户确认。
- Agent 可收集必要故障线索、提供批准过的安全指引、创建/关联请求和转工程师；不得远程给出未经批准的维修或医疗操作指导。
- 处理超期、无人认领、现场处理失败、客户要求重开；服务请求关闭后记录结果和知识库改进建议。

交付物：设备资产与服务请求设计、工程师工作台/队列、售后演示脚本、服务结果报表。

验收：从“某机构设备报修”可追到已安装设备、负责人、下一步和最终结果；超期可见、可升级；关闭后仍保留完整审计与回访记录。

### 阶段 6：验真与消费者支线（P2，取决于授权）

**目标：**为消费者提供可信引导，而非创造一个未经授权的“官方验真”系统。

任务：

- 未取得官方验真接口时，只展示官网公开的设备/治疗头/合作机构/医师验真指引与官方跳转，并记录咨询后续。
- 获得正式接口和使用许可后，单独设计验真请求、结果来源、失败/未知状态、缓存与防滥用；结果必须能回溯官方系统响应。
- 对消费者医疗问题设置明确转人工/专业人员边界；不自动判断诊断、治疗适宜性或风险等级。

交付物：非官方指引版；若获授权，再交付接口技术方案、授权记录、验真结果审计。

验收：任何“真伪”结论有官方数据源；接口断连或结果未知时显示未知并引导官方渠道，绝不显示模拟成功作为真实结果。

### 阶段 7：渠道、合规与生产化（P2，真实接入门槛）

**目标：**在有权限和合规基础上从演示迁移到真实运营。

任务：

- 根据授权接入官网表单、电话/邮件或企微等实际渠道；外部渠道通过 `lib/channels/` 抽象，不能把某渠道名写进核心业务功能。
- 明确数据控制方、处理目的、同意与撤回、最小化收集、保留/删除流程；健康信息单独评审。宣传/产品回答由法务及产品责任人审批。
- 建立 Agent 质量与风险指标：有效线索率、人工接管率、无依据回答率、错误承诺阻断率、服务超期率、客户确认解决率；先建立基线，再设目标，不预填业绩数字。
- 对新表执行 tenant RLS、权限、审计与隔离测试；schema 变更走 migration + idempotent baseline + MANIFEST；外部副作用通过事件/worker；在 fresh self-host 环境做端到端和可视化验收。
- 设定人工停用/回滚机制、故障告警与知识撤回路径；生产 Agent 发布必须由授权负责人确认。

交付物：授权与合规记录、渠道接入清单、可观测性看板、测试证据、运维/回滚手册。

验收：真实来源和责任人可审计；撤回/失败能阻断对外动作并通知操作员；RLS、关键 E2E、安装更新测试和人工验收均通过后才称为生产就绪。

### 阶段 8：作品展示与交付说明（求职版发布门槛）

**目标：**让观看者一眼分清真实实现、受控测试和静态回放，能在数分钟内看完业务闭环。

任务：

- 准备两条可点击故事：机构设备询价与人工报价审批、已售设备报修与工程师接管。每条展示输入、Agent 决策依据、工具动作、审批/人工节点、CRM 状态和最终结果。
- 对静态 GitHub Pages 演示，预录流程并标记“虚构数据/非实时模型/非正式客户发送”；链接到可公开的源码证据。历史链接若失效须修复或移除。
- 制作一页“项目边界与本人负责内容”：哪些是复用底座、哪些是新开发、哪些仅模拟、哪些尚未接入。
- 用桌面和移动端浏览器逐步验收；保存截图/录屏和脚本。README 给出直达入口及推荐点击路径。

交付物：公开演示链接、演示脚本、证据目录、功能状态清单。

验收：陌生用户无需讲解可完成两条故事；页面不存在把模拟结果写成真实系统记录的表述；所有对外源码/文档链接可打开。

## 5. 推荐实施顺序与停止点

- **作品集最小闭环：阶段 0 → 1 → 2 → 3 → 4 → 8。** 先让机构询价链路真正讲得通，再决定是否做售后。
- **完整业务演示：在以上基础上完成阶段 5。** 这时展示“销售 + 售后”的双链路。
- **真实接入：阶段 6/7 必须以企业授权和正式资料为前置。** 缺少授权时，停在可诚实展示的模拟/指引状态，不用技术手段绕过边界。

阶段间门槛：知识库未审核，Agent 不发布；价格/交期权限未定义，报价不外发；服务请求没有负责人和下一步，不进入自动分派；验真无官方接口，不出真伪结论。

## 6. 全阶段统一验收原则

每个新模块都回答：谁输入、谁消费、发出什么活动、在哪里可见、从哪里进入、谁负责下一步、配置在哪里、IA↔人工如何续接、失败如何反哺规则、架构图如何更新。开放需求必须有负责人和下一步或明确结案；外发动作尊重人的时间与可中止性。

本方案的任务目标不是“把官网页面照搬进 CRM”，而是把公开可见的业务链转化为**可追踪、可审核、可交接、可纠错**的 Agent 工作流。具体价格、SLA、资料、接口和品牌授权均待阶段 0 确认，不能从官网文案推断。
