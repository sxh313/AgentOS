# 求职展示边界

## 两个可运行表面

| 表面 | 位置 | 运行方式 | 作用 |
| --- | --- | --- | --- |
| 完整产品源码 | 主仓库 | Next.js + Supabase + Worker | 展示 Agent 全栈实现、权限、数据和异步执行 |
| 静态交互演示 | `AiNativeCrm-demo` 仓库 / GitHub Pages | 浏览器本地状态 | 展示界面、预录 Agent 流程、审批、Trace 和 Eval |

静态演示不是完整后端的替代品。它不会启动真实模型、Supabase、Worker、WhatsApp，也不会
发送客户消息。演示中的客户、商机、联系人和运行记录均为虚构或已脱敏的历史录制。

## 主项目中应突出什么

源码阅读入口保持在一条主线上：

```text
CRM / API
  -> Agent Engine
  -> Agent Runtime contract
  -> Pi Agent Runtime adapter
  -> Worker / event_log / audit / Eval
```

求职 README 不需要把所有证据、实验和历史交接文档都放在首屏。它们仍然保留在仓库中，
但应作为验证材料按需打开，而不是和产品源码并列成多个“主入口”。

## 展示页的维护边界

展示页可以拥有自己的 UI、合成数据和回放脚本；生产代码中的租户隔离、审批、审计、发送
和数据库约束不能为了适配静态演示而复制一份。演示新增能力时，必须显式标注：

- `模拟演示`：确定性浏览器逻辑；
- `真实模型录制`：历史输入输出的只读回放；
- `真实后端`：只有在主项目本地或部署环境中才成立。

这样可以避免把演示层的重复状态误认为生产架构，也避免招聘方误解为已经接入真实客户系统。

## 清理原则

`.playwright-cli/`、构建产物和本地调试日志属于临时文件，不进入公开版本库。过程证据和
架构资料可以保留，但通过 README 和文档索引降级为二级入口。核心 Agent Runtime、事件队列、
Worker、RLS 和运行记录模型在完成消费者审计前不删除。
